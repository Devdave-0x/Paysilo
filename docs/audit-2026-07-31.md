### `contracts/scripts/runPayrollViaSafe.ts`

The script exists and is registered as `npm run payroll:safe`. It contains an internal sanity check that detects `payrollAdmin != safeAddress` and throws before reaching any on-chain call. It is dead code relative to the live deployment. Not deleted yet.

## 3. Open technical questions

**Etherscan verification — empty API error.**
Every run of `hardhat verify --network sepolia` against Etherscan returns:

```
HHE80001: The request to https://api.etherscan.io/v2/api failed with the message "".
```

No HTTP error code, no body. Blockscout and Sourcify are both verified. Likely an Etherscan API reliability issue or rate limit silent failure. Options: retry with exponential back-off, use `--force` flag on a later attempt, or accept Blockscout + Sourcify as sufficient for the submission. **No action required to unblock anything else.**

**Should the stale Safe docs be corrected before submission?**
The ARCHITECTURE and SETUP docs contradict the live deployment in multiple places. The root cause (Safe + Nox `validateInputProof` incompatibility, documented in `docs/feedback.md` friction #7) is already captured. The docs can be updated now or left as-is with a note in the submission that the intended design used Safe but the live workaround uses the EOA. Decision is the team's.

**Vercel deployment protection.**
Disabled via dashboard (user action). Not a code issue.
